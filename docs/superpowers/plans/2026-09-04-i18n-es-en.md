# i18n ES/EN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an instant ES/EN language switch to the portfolio, translating every user-facing string (UI chrome + the long per-project case-study prose in `src/data/projects.js`).

**Architecture:** A `LanguageContext` (structural copy of the existing `ThemeContext`) holds `lang` state persisted to `localStorage`, defaulting to `'es'`. Bilingual content is stored as `{ es, en }` objects — in place for data-file fields, and in a new `src/i18n/strings.js` dictionary for JSX chrome text. A `useTranslate()` hook returns a `t(value)` resolver that components call inline.

**Tech Stack:** React 19 Context API only — no new dependency (react-i18next was considered and rejected in the spec; this app has 2 languages, no routing, no pluralization).

**Spec:** `docs/superpowers/specs/2026-09-04-i18n-es-en-design.md`

## Global Constraints

- Default language is always `'es'` unless `localStorage['portfolio-lang'] === 'en'` — never detect `navigator.language` or `prefers-...`.
- Switch is instant (React state), no route change, no reload.
- `translate(lang, value)` falls back to `value.es` when the active language's key is missing, and returns `value` unchanged when it isn't a `{es,en}` object (plain string passthrough for anything not yet migrated).
- Every literal Spanish string identified in this plan gets an English translation; every literal English string found already in the codebase (Navbar/Footer nav labels, "Get In Touch", `ProjectTestimonial`'s "What The Client Says") gets a **Spanish** translation added, since the site must default to Spanish and currently doesn't for those spots.
- No test suite exists in this project — verification is `npm run build` plus the manual QA pass in the final task.
- Preserve all existing GSAP animation logic, class names used as GSAP selectors (e.g. `.hero-greeting`, `.story-ghost-text`), and Tailwind classes untouched — only text content and its wrapping in `{es,en}` changes.

- [ ] **Step 1: Create `src/context/LanguageContext.jsx`**

```jsx
import { createContext, useContext, useEffect, useMemo, useState } from 'react'

const LanguageContext = createContext(null)

export function LanguageProvider({ children }) {
  const [lang, setLang] = useState(() => {
    const stored = localStorage.getItem('portfolio-lang')
    return stored === 'en' ? 'en' : 'es'
  })

  useEffect(() => {
    document.documentElement.lang = lang
    localStorage.setItem('portfolio-lang', lang)
  }, [lang])

  const toggleLang = () => setLang((l) => (l === 'es' ? 'en' : 'es'))

  const value = useMemo(() => ({ lang, toggleLang }), [lang])

  return (
    <LanguageContext.Provider value={value}>
      {children}
    </LanguageContext.Provider>
  )
}

export const useLanguage = () => {
  const ctx = useContext(LanguageContext)
  if (!ctx) throw new Error('useLanguage debe usarse dentro de LanguageProvider')
  return ctx
}

export function translate(lang, value) {
  if (value && typeof value === 'object' && ('es' in value || 'en' in value)) {
    return value[lang] ?? value.es ?? ''
  }
  return value
}

export function useTranslate() {
  const { lang } = useLanguage()
  return (value) => translate(lang, value)
}
```
